# 🧠 HealthSphere — Predictive AI & Machine Learning

## 📌 Overview

This repository contains the **Predictive Machine Learning component** of the **HealthSphere** platform.

HealthSphere is an AI-powered health platform designed to help users better understand and monitor their health through personalized health profiles, health metrics, medical document analysis, predictive risk assessment, and an AI-powered conversational assistant.

This repository focuses specifically on the **structured-data Machine Learning pipeline**.

Its main responsibilities are:

- Dataset collection and generation
- Data exploration and analysis
- Data preprocessing
- Feature engineering
- Machine Learning experimentation
- Model training
- Model evaluation
- Model explainability
- Model versioning
- Prediction API integration

> The predictive model is intended to provide informational health-risk assessments and does not provide a medical diagnosis.

---

# 🎯 Objective

The objective of the Predictive ML component is to transform structured health information into an interpretable health-risk assessment.

Conceptually:

```text
Patient Health Data
        ↓
Data Preprocessing
        ↓
Feature Engineering
        ↓
Predictive ML Model
        ↓
Risk Assessment
        ↓
Explainability
```

Example input features may include:

- Age
- Sex
- BMI
- Blood pressure
- Health observations
- Medical history
- Lifestyle information
- Relevant laboratory measurements

The exact features and prediction target will be determined during dataset exploration and model development.

# 🧬 Dataset

## Synthea

For the initial phase of the project, HealthSphere uses synthetic healthcare data generated by **Synthea**.

Synthea is an open-source synthetic patient generator that provides realistic but fictional electronic health records.

Using synthetic data allows the project to explore healthcare data structures without relying on real patient records.

### Initial dataset

The initial dataset contains a sample of synthetic patient records exported in CSV format.

Raw Synthea data is stored under:

```text
data/raw/synthea/
```

The dataset includes files such as:

```text
patients.csv
conditions.csv
observations.csv
medications.csv
allergies.csv
encounters.csv
procedures.csv
immunizations.csv
careplans.csv
devices.csv
imaging_studies.csv
supplies.csv
claims.csv
claims_transactions.csv
organizations.csv
providers.csv
payers.csv
payer_transitions.csv
```

Not all files will necessarily be used by the final Machine Learning model.

The most relevant datasets will be selected during the data exploration and feature-engineering stages.

---

# 🔎 Dataset Usage

Synthea data can be used in HealthSphere for several purposes:

### 1. Data exploration

Understand the structure and relationships between synthetic patient records.

### 2. Patient simulation

Provide realistic synthetic health profiles for development and testing.

### 3. Feature construction

Extract relevant health variables from multiple Synthea CSV files.

For example:

```text
patients.csv
      +
observations.csv
      +
conditions.csv
      +
medications.csv
      +
encounters.csv
      ↓
Feature Engineering
      ↓
ML-ready Dataset
```

### 4. Machine Learning experimentation

The processed dataset can later be used to train and evaluate predictive models.

### 5. Testing

Synthetic patients can be used to test the complete HealthSphere prediction workflow without exposing real patient information.

# 🎯 Prediction Target

The final prediction target has **not yet been fixed during the initial dataset exploration phase**.

A possible HealthSphere output could later use categories such as:

```text
Low
Moderate
Needs Attention
```

However, these categories must not be created arbitrarily.

The final target definition must depend on:

- The selected dataset
- Available labels or outcomes
- Validated medical references
- The intended use of the predictive system

This decision will therefore be finalized before model training.

---

# 🤖 Model Development

XGBoost is the approved primary predictive model. A simple interpretable baseline (such as Logistic Regression) will be retained for comparison. Target validation must pass before fitting any model; release depends on measured evaluation rather than the algorithm choice alone.

---

# 📊 Model Evaluation

Depending on the final prediction task, evaluation may include:

- Precision
- Recall
- F1-score
- ROC-AUC
- Confusion Matrix

For health-risk classification, particular attention will be given to the model's ability to correctly identify cases requiring attention.

The exact explainability technique will depend on the final selected model.

# 💾 Model Serialization

After training and validation, the final preprocessing pipeline and model will be serialized together.

Example:

```text
models/
└── health_risk_pipeline.joblib
```

The objective is to preserve:

```text
Preprocessing
      +
Feature Transformations
      +
Trained ML Model
      ↓
health_risk_pipeline.joblib
```

This ensures that the same transformations used during training are also applied during production inference.

# Stage 8 ML readiness

HS-010 froze the specification used by the experimental five-year incident
essential-hypertension model. Stage 9 then trained and selected the committed v1 artifact.

```bash
uv sync --locked --dev
uv run ruff format --check .
uv run ruff check .
uv run pytest -q
uv run python scripts/analyze_ml_readiness.py data/raw/synthea_5000_reproducible/csv
```

The full decision and reproducible evidence are in [HS-010 ML readiness](docs/ml/HS_010_ML_READINESS.md). The large generated Synthea cohort remains ignored.

## Experimental hypertension training

The frozen HS-010 training pipeline predicts the experimental probability of a first recorded essential-hypertension event within five years after an eligible paired-BP encounter. Reproduce it from the documented local Synthea cohort with:

```bash
uv run python scripts/train_hypertension_model.py data/raw/synthea_5000_reproducible/csv
```

The pipeline writes versioned artifacts to `artifacts/hypertension_5y/v1/`; see [the model card](docs/evaluation/MODEL_CARD.md) and [evaluation report](docs/evaluation/HS_010_MODEL_EVALUATION.md). HealthSphere backend supplies `hypertension_features_v1`; `healthsphere-agent` does not calculate the probability. This synthetic-data model is not clinically validated and must not be used for diagnosis, treatment, emergency triage, or clinical decisions.

## Internal inference service

HS-002 remains the authoritative inference transport contract. HS-011 serves the frozen
`hypertension_5y_v1.0.0` model behind `POST /internal/v1/inferences`; no browser-facing
prediction route exists. Configure an opaque service credential and start the API:

```bash
export HEALTHSPHERE_INTERNAL_API_TOKEN='replace-with-a-real-secret'
uv run uvicorn healthsphere_ai.api:app --host 127.0.0.1 --port 8001
```

Readiness is available at `GET /health`. Startup loads the native XGBoost model and trusted
joblib preprocessor once, verifies artifact hashes and frozen metadata compatibility, and
fails closed when verification does not pass. Serving requires no raw Synthea files.

```bash
curl -X POST http://127.0.0.1:8001/internal/v1/inferences \
  -H 'Authorization: Bearer replace-with-a-real-secret' \
  -H 'X-Request-ID: c4a760a8-7d0b-4f98-9652-244be1ebcc2e' \
  -H 'Content-Type: application/json' \
  -d '{
    "schema_version":"1.0",
    "request_id":"c4a760a8-7d0b-4f98-9652-244be1ebcc2e",
    "subject_ref":"f630d635-64e2-432b-8175-60f61d220d4d",
    "features":{
      "age_years":42,
      "systolic_blood_pressure":128,
      "diastolic_blood_pressure":82,
      "heart_rate":76,
      "bmi":24.7,
      "sex_at_birth":"female",
      "smoking_status":"never"
    }
  }'
```

The completed response preserves the versioned HS-002 status/result/provenance envelope.
Its score is explicitly an `uncalibrated_experimental_probability_estimate`; it is not a
diagnosis, calibrated clinical probability, risk category, cutoff, or treatment trigger.
